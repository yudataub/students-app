# desktop/ — הגרסה המקומית של students-app

תיקייה זו היא **גרסה נפרדת שרצה על המחשב של המשתמש בלבד** (לא באינטרנט), שנבנתה כדי לפתור בעיה: האתר החי (`../index.html`, ב-GitHub Pages) שומר הכל ב-`localStorage` של הדפדפן שמוגבל לכ-5MB, ועם הרבה תלמידים+תמונות זה התמלא ("אין מספיק מקום — נסה למחוק תלמידים ישנים").

מסמך האפיון המלא: [`../docs/superpowers/specs/2026-08-12-desktop-local-app-design.md`](../docs/superpowers/specs/2026-08-12-desktop-local-app-design.md) — קרא אותו לפני שינויים ארכיטקטוניים.

## מבנה

```
desktop/
  server.py       ← שרת Python (stdlib בלבד, בלי pip install), פורט 8733, 127.0.0.1 בלבד
  index.html       ← עותק מותאם של index.html הראשי — לא לערוך ידנית סתם, ר' למטה
  data/             ← נוצר אוטומטית, ה-.gitignore חוסם אותו (תמונות ילדים — לא נכנס לריפו!)
    data.json         ← כל מצב האפליקציה (תלמידים, תמונות, ניקוד, סידורי ישיבה)
  הפעל.bat         ← לחיצה כפולה: מפעיל את השרת + פותח דפדפן אוטומטית ל-localhost:8733
```

## איך זה עובד (הרעיון המרכזי)

`desktop/index.html` הוא **כמעט זהה מילה-במילה** ל-`../index.html` הראשי. ההבדל היחיד המהותי: בראש תג ה-`<script>` יש שכבת-תיווך (IIFE) שמחליפה את `window.localStorage` האמיתי באובייקט מדומה (`Object.defineProperty(window, 'localStorage', ...)`), שנטען **סינכרונית** (XMLHttpRequest חוסם) מהשרת המקומי בעליית הדף, וכל `setItem` שולח (עם debounce) עדכון ל-`POST /api/data`.

**המשמעות: כל שאר הקוד בקובץ ממשיך להשתמש ב-`localStorage.getItem/setItem` בדיוק כמו קודם** — הוא פשוט לא יודע שהוא כותב לדיסק ולא לדפדפן. זה כולל דברים שיתווספו בעתיד באתר הראשי (סידורי ישיבה חדשים, מפתחות הגדרות וכו') — **לא צריך לגעת בשכבת התיווך כשמוסיפים פיצ'ר חדש**, היא כללית ולא יודעת כלום על שמות מפתחות ספציפיים.

שינויים נוספים בעותק (בסוף הקובץ, אחרי כל שאר הקוד — כדי לנצח הגדרות קודמות באמצעות hoisting):
- `async function initFirebase() { }` מוגדר מחדש כריק — מנטרל לגמרי את סנכרון הענן (Firebase), כך שאין שום קריאת רשת חיצונית. שאר פונקציות הענן (`cloudSaveNow` וכו') נשארות בקובץ אך אינרטיות (תמיד `_fbUser`/`_fbFirestore` נשארים `null`) — לא נמחקו כדי לצמצם סיכון לשבירת syntax בקובץ ענק.
- `desktopImportBackup(e)` — קולט קובץ `backup.json` (מיוצא מהאתר הראשי) ושולח אותו ישירות ל-`POST /api/data`.
- `<style>.cloud-section{display:none!important}</style>` — מסתיר את כל ממשק הענן/שיתוף מההגדרות (הכפתורים עדיין קיימים ב-DOM, פשוט מוסתרים).
- ב-HTML: סקשן חדש בהגדרות ("📥 ייבוא גיבוי מהאתר") עם `class="desktop-section"` (לא `cloud-section`, כדי לא להיעלם עם ה-CSS למעלה).

## ⚠️ כלל ברזל: סנכרון בין שני עותקי index.html

**כל שינוי בפיצ'ר קיים באתר הראשי (`../index.html`) חייב להיכנס גם ל-`desktop/index.html`**, אחרת שתי הגרסאות יתפצלו וילכו לאיבוד. הדרך הכי בטוחה:

1. תעשה את השינוי ב-`../index.html` קודם, תבדוק שם.
2. תעתיק את **אותו diff המדויק** (אותן שורות, אותו מיקום יחסי) ל-`desktop/index.html` — **חוץ אם** השינוי נוגע ספציפית ב-Firebase/ענן/שיתוף (זה כבר שונה בכוונה בין הגרסאות, ר' למעלה).
3. הרץ שוב את בדיקת התחביר על **שני** הקבצים (ר' למטה) — לא רק אחד.

אם שינית פיצ'ר גדול, כדאי לשקול סקריפט קטן חד-פעמי שמוודא שההבדל בין שני הקבצים הוא רק הבלוקים הידועים (שכבת האחסון, ניטרול Firebase, ה-CSS, וה-import UI) ולא שום דבר אחר — כדי לתפוס פספוס.

## פרטים טכניים

- **פורט**: 8733, קבוע בשני מקומות — `server.py` (`PORT = 8733`) ו-`desktop/index.html` (השכבה קוראת ל-`location.origin`, אז זה גמיש אוטומטית — אין צורך לתאם ידנית אם משנים פורט, רק בקובץ python).
- **פורמט `data.json`**: אובייקט שטוח `{key: "JSON string", ...}` — בדיוק כמו שה-`localStorage` האמיתי מחזיק מפתחות (`students`, `behaviorTypes`, `deletedTombstones`, `importedNamesMap`, `seating_<שם כיתה>` — כל אחד ערכו הוא **מחרוזת JSON**, לא אובייקט מקונן). זה גם הפורמט המדויק של `backup.json` שהאתר הראשי מייצא (`exportFullBackup()` ב-`../index.html`) — כך שהייבוא הוא פשוט POST ישיר בלי המרה.
- **כתיבה אטומית**: `server.py` כותב ל-`data.json.tmp` ואז `os.replace()` — כדי שסגירת השרת/מחשב באמצע שמירה לא תשבור את הקובץ.
- **אבטחה**: `server.py` חוסם גישת GET ל-`/data/*` ול-`*.py` (403) — כדי שלא יהיה אפשר לגלוש בדפדפן ולראות/להוריד את `data.json` הגולמי (עם כל תמונות הילדים) או את קוד השרת. השרת מאזין רק ל-`127.0.0.1` — לא נגיש מרשת הבית או מהאינטרנט.
- **בדיקת תחביר מהירה** (הרץ אחרי כל שינוי, על שני הקבצים):
  ```bash
  node -e "const fs=require('fs');['../index.html','index.html'].forEach(p=>{const h=fs.readFileSync(p,'utf8');[...h.matchAll(/<script>([\s\S]*?)<\/script>/g)].forEach(m=>new Function(m[1]));console.log(p,'OK');});"
  python -c "import ast; ast.parse(open('server.py', encoding='utf-8').read()); print('server.py OK')"
  ```
- **הרצה לבדיקה**: `python server.py` מהתיקייה הזו (או `desktop\הפעל.bat`), ואז `http://localhost:8733`. סופי שורות בקבצים: CRLF (כמו הראשי) — שמור על זה בעריכות (ר' [`../CLAUDE.md`](../CLAUDE.md)).

## מה **לא** נכנס לגרסה הזו (בכוונה)

- גישה מהטלפון/רשת הבית — `127.0.0.1` בלבד.
- סנכרון בין הגרסה המקומית לאתר החי אחרי הייבוא הראשוני — חד-כיווני, חד-פעמי בלבד (אין "push חזרה" לענן).
- אריזה כ-exe/Electron אמיתי — זה סקריפט Python + קובץ bat, לא אפליקציה מותקנת.
- ריבוי מכשירים/משתמשים בו-זמנית מול אותו `data.json`.
